# Project creation decision tree

## 1. Choose the project type
- **Android app with no starter code:** `No Activity` only when the user explicitly wants to create Activity/manifest setup manually.
- **Small conventional app:** `Empty Activity` or the simplest equivalent offered by the installed CoGo template set.
- **App with a sample floating action button:** `Basic Activity`; remove/replace sample behavior deliberately.
- **App whose navigation structure needs a drawer or bottom navigation:** use a matching navigation template only when its scaffold fits the actual information architecture.
- **Kotlin Compose UI:** choose `Compose Activity`/the Compose-enabled template.
- **Java + XML:** choose a Java Views/XML template.
- **Kotlin + XML:** choose a Kotlin Views/XML template.
- **Plugin or library:** do not treat it as an ordinary installable app; Quick Build eligibility differs.

Exact template names and availability can change. Inspect the templates shown by the installed CoGo version.

## 2. Fill project identity and language
Example for the converter:
- App name: `UnitConverter`
- Package: `com.example.unitconverter`
- Language/UI: Kotlin + XML
- Minimum SDK: choose based on intended oldest Android version and dependencies; do not pick a number just because a tutorial uses it.
- Gradle DSL: keep the generated default unless the user has a reason to choose the other DSL.

The package is an example, not a requirement. After project creation, verify the actual generated package, source path, and namespace.

## 3. Identify the real file structure
Common paths, conditional on the template:
- `app/src/main/AndroidManifest.xml`
- `app/src/main/java/<package>/MainActivity.kt` or `.java`
- `app/src/main/res/layout/activity_main.xml` (Views/XML only)
- `app/src/main/res/values/strings.xml`
- `app/build.gradle.kts` or `app/build.gradle`
- root `build.gradle(.kts)`, `settings.gradle(.kts)`, `gradle-wrapper.properties`
- optional `gradle/libs.versions.toml`

Do not assume every project uses an `app` module or Kotlin DSL. Inspect the tree.

## 4. UI architecture
### Views/XML
- XML defines views and IDs.
- Java/Kotlin code finds IDs or uses generated view binding.
- Every `R.id.name` must match an actual ID in the loaded layout.
- Keep the manifest/theme generated by the template unless the app needs a specific declared component/permission.

### Compose
- UI is declared in Kotlin `@Composable` functions.
- State changes should drive recomposition.
- Compose compiler/plugin/dependency configuration must be compatible with the project toolchain.
- Use a Compose template instead of pasting Compose imports into a Views-only project.

## 5. Dependency decision
Before adding a dependency:
1. Check whether the project/template already provides it.
2. Confirm the library supports the project's min SDK and configured AGP/Kotlin.
3. Check whether the required artifact is already cached if working offline.
4. Add the smallest necessary configuration in the correct Gradle DSL.
5. Sync and inspect the first resolution/configuration error.
6. Record the exact coordinate and version used.

## 6. Build sequence
1. Wait for project initialization and sync.
2. Build/run the unchanged starter project.
3. Add one feature at a time.
4. Build/run after each coherent change.
5. Exercise the feature and check logs.
6. Use Quick Build only after the normal build works and only if the project/edit is eligible.
7. Generate and test the release artifact separately when distributing.
